## 1. 진행 상태의 판단 기준

다른 에이전트의 신규 파일과 수정이 다수 미커밋 상태이므로 Git 커밋 이력만으로 진행도를 판단하지 않았다. 검토 시점의 작업 트리에 실제 존재하는 기능을 기준으로 후속 범위를 정한다. 파일이 있다는 이유만으로 통과·완료로 표시하지 않는다.

- **기반 구현 존재:** 대응 코드가 확인되며 9분류 변경에 재사용할 수 있음.
- **전환 필요:** 현재 10분류 등의 가정이 제공 모델과 맞지 않음.
- **증거 일부:** 실행 결과 파일은 있으나 실제 모델·현재 9분류·화면 전체를 검증하지 않음.
- **미완료:** 연동 코드·최종 자산·검증 증거·구조 정리 중 필수 결과가 없음.

계획의 현재 상태는 조사 시점의 스냅샷이다. 다른 에이전트가 계속 작업하면 담당 파일을 편집하기 직전에 최신 내용을 다시 읽고 완료 항목을 갱신한다. 이 계획의 역할 분담은 자동 에이전트 실행을 뜻하지 않는다.

## 3. 확정할 9분류 동작

### 3.1 분류·계약

기쁨·활력 / 만족·감사 / 안정·자신감 / 불안 / 슬픔 / 분노 / 객관적 서술 / 의문 / 놀람·당황의 9개 앱 ID를 사용한다. [상위 계획 4절](MIGRATION_PLAN_2026-11-17.md#4-9분류-계약과-카드-판정)의 매핑이 기준이다. 특히 모델의 분노·슬픔·불안 순서와 앱의 불안·슬픔·분노 순서가 다르다.

목표 taxonomy는 emotion-cardex-3plus9-v1, 도감은 27슬롯이다. neu_3은 새 taxonomy에서 놀람·당황, neu_4는 비사용이다. 세부 확률을 합산해 긍정·부정·중립 통계를 계산한다. 카드 배지는 대표 세부감정의 소속이며, 합산 대분류 최대값과 달라질 수 있다. strict-gt 카드 경계·동률 정책은 그대로 유지한다.

### 3.2 제공 모델 정정 및 운영 후보

두 제공 체크포인트의 config는 structure=FL이다. 예제에서 IH일 때만 실행되는 가지 선택을 이번 모델에 적용하지 않는다. 실제 출력은 각각 9클래스 전체 softmax이며 앙상블은 두 확률을 50:50으로 평균한다. 이전 보고의 조건부 확률 설명을 철회한다.

운영 기본 후보는 제공 문서의 ensemble_seed42로 잡되 단일 CE·RDrop도 같은 입력으로 평가한다. 선택 지표·자료가 부족하면 “앙상블이 더 정확함”으로 확정하지 않는다. 모델 선택을 사용자 UI의 신규 옵션으로 추가하지 않는다. 모델 선택·자원 설정은 운영 구성에서 관리한다.

예제는 긴 입력을 자동으로 256토큰에 자른다. 서비스에서는 먼저 전체 토큰 수를 확인하고 초과 시 분석 불가로 응답한다. 10,000자까지 보관 가능한 원문은 유지한다. 예제의 문맥 단위 dialogue와 앱의 일기 텍스트 사용 간 차이는 대표 합성 샘플·평가 자료로 검수하고, 분류값을 감정 강도로 표현하지 않는다.

### 3.3 자산 대조

최신 파일명과 바이트 내용을 다시 확인했다. 현재 PNG는 발급용 27장과 빈 템플릿 1장, 총 28개다. 감정·단계 키 누락·중복 및 27장 간 동일 SHA-256은 없다. 이름이 `.png`였던 별도 파일은 현재 목록에 없다.

| 앱 감정 | 단계별 캐릭터 (01 → 02 → 03) | 현재 상태 |
|---|---|---|
| pos_1 기쁨·활력 | 아기여우 → 구미호 → 구미호 인간형 | 기쁨 3장 확보 |
| pos_2 만족·감사 | 아기곰 → 반달가슴곰 → 웅녀 | 만족 3장 확보 |
| pos_3 안정·자신감 | 아기거북 → 늙은거북 → 현자거북 | 안정 3장 확보 |
| neg_1 불안 | 아기고양이 → 검은고양이 → 고양이수인 | 추가된 불안 3장 확보 |
| neg_2 슬픔 | 아기늑대 → 리더늑대 → 늑대인간 | 슬픔 3장 확보 |
| neg_3 분노 | 아기호랑이 → 백호 → 호랑이산군 | 수정된 파일명으로 분노 3장 확정 |
| neu_1 객관적 서술 | 아기코끼리 → 어른코끼리 → 가네샤 | 객관적서술 3장 확보 |
| neu_2 의문 | 아기원숭이 → 스패너원숭이 → 손오공 | 의문 3장 확보 |
| neu_3 놀람·당황 | 아기토끼 → 어른토끼 → 달토끼 | 파일명 놀람을 모델의 놀람·당황 통합 클래스로 매핑 |

[카드 이미지 인수 확인서](CARD_ASSET_INTAKE_2026-11-17.md)에 정확한 27개 파일명·크기·SHA-256 식별값과 실제 파일 링크를 기록했다. `01_놀람_아기토끼_번개.png`는 마지막 재수정 후의 최신 내용으로 식별값을 갱신했다. 빈 템플릿은 발급 카드 수에 포함하지 않는다.

기쁨·분노의 기존 확인에 이어 불안 1단계·놀람 2단계 샘플을 열어 프레임이 포함된 full_card 이미지임을 확인했다. 기본 카드 18장은 627~628×836, 불안·놀람 6장은 1086×1448, 분노 3장은 1060×1484다. 전체 27장의 개별 배치·텍스트 안전 영역은 IMAGE 작업에서 검수한다. **이미지 제공 대기는 해소됐지만 앱 manifest·배포 경로·렌더러 연결은 아직 미완료다.**

### 4.1 구현을 시작할 때 지킬 순서

1. 최신 작업 트리와 편집 담당 파일을 확인하고 기존 기능·미커밋 변경을 보존한다. 스키마·IDs부터 확정한다.
2. N9-FE와 N9-MODEL을 병행할 수 있다. N9-IMAGE는 확보·매핑된 27장의 배포 자산 반영과 full_card 렌더링을 이때 진행한다.
3. N9-DATA는 확정된 9분류 mock으로 선행할 수 있다. 실제 모델을 붙인 통합 통과는 MODEL 이후다.
4. N9-OPS·N9-VISUAL의 기반 검증은 준비되는 부분부터 진행하되, 최종 판정은 실제 모델·최종 카드 전체로 한다.
5. 통합·시각 결과를 확인한 뒤 구형 파일을 보관하고 실행 문서를 마무리한다. 코드가 import하는 구형 scripts를 먼저 이동하지 않는다.

## 5. 파일별 주의할 미완료 사항

### 5.1 모델·계약

- backend/app/ml/predictor.py의 10감정 manifest 전제·REQUIRED_CHECKPOINT_FILES·AutoModelForSequenceClassification 로딩을 실제 포맷에 맞춘다. generic 6감정 CLI 호환 코드가 운영 모델 선택을 대신하지 않게 한다.
- 제공 ensemble.json은 Windows 절대경로를 포함한다. Linux에서 역슬래시 경로에 Path.name을 적용해도 Windows basename처럼 처리되지 않으므로, 명시적인 두 구성원 이름·운영 상대경로로 해결한다. 학습 PC 절대경로가 존재하면 이를 우선 사용하는 정책도 제거한다.
- 두 모델의 라벨 의미·순서·tokenizer·입력 길이·가중치 해시를 일치 검증한다. 현재 해시와 manifest 값의 일치는 과거 확인 사실이며, 실제 운영 복사본은 인수 시 다시 확인한다.
- 기존 schema 성공 응답의 EmotionId enum, neu_[1-4] 정규식, ties max 10, BE/FE 중복 ID·버전, 인수 samples와 mock을 함께 갱신한다. 스키마 문자열만 바꾸고 10차원 분포를 남기지 않는다.
- 앙상블 메모리·동시 요청 시 장치 오류·inference_mode·평가 모드·bf16 지원을 검증한다. 개발 PC의 GPU 라이브러리 버전이 운영 컨테이너에서 그대로 지원된다고 가정하지 않는다.

### 5.2 프론트·저장·이미지

- domain/index.js가 기존 core.js·statistics.js를 부수효과 import한다. Vue만 수정해서 기존 전역 CardexCore.TAXONOMY/IDS가 10분류로 남지 않게 의존 경로를 정리한다. 구형 단일 HTML을 비교 기준으로 사용할 동안에는 원래 화면을 보존해 재현할 방법을 먼저 확보한다.
- snapshotStorage는 현재 원문 v1→v2 이전과 10감정 분석 복원을 지원한다. 9분류 호환성 이전이 완료된 것은 아니다. 구형 결과를 새 model_version으로 바꿔 재사용하지 말고 원문 재분석으로 연결한다.
- 현재 복원 함수는 저장소를 읽고 상태를 복원하며 pending 기록을 일괄 재분석하지 않는다. 오래된 기록의 분석 요청 경로·재시도 가능 UI를 마련하고, 무한 자동 재요청·중복 요청을 피한다. 네트워크 요청 취소·이전 응답 무시는 기존 Coordinator를 재사용한다.
- analysisClient는 fetch에 AbortSignal을 전달하지만 요청 시간 제한이 없다. 실제 추론 시간·Nginx 60초 설정과 맞춰 끝나지 않는 분석 상태를 방지하는 실패·재시도 처리를 정의한다.
- cardAssets는 full_card kind를 받아도 cardRenderer는 현재 characterSVGString을 통해 캐릭터 사각 영역에 전체 카드를 넣는다. 메타데이터를 두 번 표시하거나 카드 속 카드로 작아지는 문제를 실제 샘플로 해결한다. 기존 2:3 카드 외곽과 PNG 크기를 보존하면서 원본 아트를 비율 유지 배치한다.
- 카드 이미지 kind에 따라 중립 SVG 표식 표시와 테마 색 적용 범위를 정한다. 원본 full_card 색까지 테마 토큰으로 바꾸지 않는다. PNG 내보내기용 이미지 data URI 포함과 글꼴 로딩도 확인한다.
- 카드 manifest는 읽기 실패 시 기존 placeholder로 돌아가는 경로가 있다. 최종 검증에서 27개 모두 provided이며 실제 파일이 열리는지 확인해 임시 자산 fallback이 실패를 숨기지 않게 한다.

### 5.3 실행·증거·정리

- .env.example의 기본 모델 경로는 아직 기존 6감정이다. compose 마운트는 체크포인트 하나만 연결하므로 앙상블 형제 폴더를 모두 읽는 형태로 수정한다. 사용자 .env 원문은 문서나 로그에 공개하지 않는다.
- .dockerignore에 tmp가 빠져 있어 대용량 모델과 원본 이미지가 빌드 컨텍스트에 들어갈 수 있다. .gitignore와 함께 원본 보존·제외를 명시한다. 최종 이미지 자산은 별도 검수 경로에 복사한다.
- 기존 OPS의 create_host_path:false 결과는 빈 디렉터리 자동생성이 관측됐다. 모델 경로 존재 검사를 시작 안내에 추가하고, ready 503을 성공 기동으로 오인하지 않게 한다.
- QA 스크립트 존재와 실행 결과 존재를 구분한다. 현재 browser-e2e-results.json과 스크린샷 파일이 없으므로 브라우저 통과로 표시하지 않는다. 기존 mock ops JSON을 실제 모델 인수 결과로 변경하지 않는다.
- README의 구형 명령, docs/openapi.yaml, frontend/docs/API_CONTRACT.md, Docker 안내, MODEL_INTAKE와 contract README를 현재 계약에 맞춘다. BASE 문서는 역사적 10분류 기준선으로 보존하고 최신 실행 계획을 링크한다.

## 8. 최종 완료 판정

기존 10분류 서비스의 기반 구현을 보존·전환해, 실제 9분류 모델과 최종 27키 이미지로 기록 작성부터 분석·카드 발급·통계·도감·새로고침 복원까지 동작해야 한다. 디자인 비교·데이터 보존·Nginx/Compose 실행·복구 증거가 있고 활성 코드·문서가 같은 계약을 가리켜야 한다. 이 조건을 충족하기 전에는 전체 전환 완료나 배포 준비 완료로 보고하지 않는다.
