## 1. 재확인 결과

최신 재수정 기준: 이름이 `.png`였던 별도 파일은 현재 목록에서 사라졌고, `01_놀람_아기토끼_번개.png`는 2,165,392 bytes·SHA-256 앞 12자리 `7c0e9561a0a7`의 파일로 확인했다. 같은 이름의 이전 내용과 혼동하지 않도록 아래 표도 최신 바이트 기준으로 갱신했다.

사용자가 수정한 파일명을 기준으로 모든 PNG의 헤더·크기·SHA-256을 확인했다. 폴더의 PNG 파일은 총 28개다. 감정명과 단계 접두어 `01_`·`02_`·`03_`에 해당하는 카드는 27개이며 9감정 각각 3개씩 있다. 감정·단계 키 누락 0건, 중복 키 0건, 27장 간 동일 SHA-256 0건이다.

이전 계획의 “불안 3장 미제공”, “놀람·당황 후보 3장 라벨 미확정” 조건은 해소되었다. 파일명 `놀람`은 9분류 모델의 통합 라벨 `놀람·당황` 및 새 taxonomy의 `neu_3`으로 매핑한다. 이 이름을 근거로 모델을 놀람·당황 2개 클래스로 나누지 않는다.

이번 작업은 원본 파일 읽기·메타데이터 확인·문서 개정이다. 파일명 변경·이동·이미지 가공·manifest 수정·모델 실행·브라우저 테스트를 수행하지 않았다. 아래 경로는 실제 파일을 여는 상대 링크다. SHA-256은 원본 식별을 위해 앞 12자리만 표기한다.

## 4. 이미지 규격과 화면 연결 주의사항

- 기본 6감정 18장(기쁨·만족·안정·슬픔·객관적 서술·의문)은 627~628×836이다.
- 불안·놀람 각 3장, 총 6장은 1086×1448이다. 분노 3장은 1060×1484다.
- 불안 1단계와 놀람 2단계를 직접 열어 프레임 포함 완성 카드 이미지를 확인했다. 이전 조사에서 기쁨·분노 샘플도 확인했다. 전체 27장의 개별 시각 검수는 후속 이미지 작업에서 수행한다.
- 원본 비율은 약 3:4 또는 5:7로 기존 화면·PNG 출력의 2:3과 다르다. 자르거나 늘리지 않고 비율을 보존해 배치한다.
- 현재 앱의 캐릭터 영역에 전체 카드를 작은 이미지로 끼우는 경로를 그대로 쓰지 않는다. `full_card` 실제 렌더링 분기, 메타데이터 안전 영역, 이중 프레임·중복 텍스트를 검수한다.
- 목록·도감·상세·1080×1620 PNG가 동일한 카드 키와 원본을 참조해야 한다. 화면 테마를 바꿔도 제공된 원본 아트의 색을 임의 변경하지 않는다.

## 5. 남은 IMAGE-01 업무와 완료 기준

자산 제공 대기는 해소되었으며, 다음은 FE·QA/디자인이 수행할 연결 작업이다.

1. 위 매핑을 기준으로 필요한 27장만 버전/해시가 포함된 배포 자산 경로에 복사한다. `tmp` 원본은 보존한다.
2. 현재 `frontend/public/assets/cards/manifest.json`의 10분류·30개 placeholder를 9분류·27개 실제 파일 항목으로 전환한다. `kind=full_card`, 카드 키·stage·taxonomy·출처를 확인하고 `all_provided` 상태를 검증한다.
3. 상세·홈·보관함·도감·PNG에 같은 이미지 조회와 렌더링을 적용한다. 존재하지 않는 파일이 placeholder fallback에 가려지지 않게 검증한다.
4. 27개 HTTP 자산 응답, 3단계별 구별, 모든 테마·뷰포트에서 비율·가림·텍스트 위치, PNG와 화면 일치를 확인한다.
5. 시각 비교·실제 동작·결과 보고서까지 확보한 후 IMAGE-01을 완료로 바꾼다.

현재 앱 manifest는 여전히 30개 placeholder이고 제공 PNG는 public 경로에 연결되지 않았다. **원본 27장 확보 완료와 앱 이미지 기능 완료를 구분한다.** 모델·데이터·운영 계획의 다른 미완료 항목은 [후속 계획](REMAINING_WORK_PLAN_2026-11-17.md)을 따른다.
