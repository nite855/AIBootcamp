# 디자인 전환 기준선 · BASE-01

> 이 문서는 전환 전 메인 디자인의 기록이며 10감정·30슬롯을 포함한다. 이후 목표는 9감정·27슬롯으로 개정되었다. 현재 Vue 작업 현황과 허용 변경·미완료 검증은 [9분류 전환 계획](../../../docs/MIGRATION_PLAN_2026-11-17.md)·[완성 계획](../../../docs/REMAINING_WORK_PLAN_2026-11-17.md)이 우선한다. 아래 캡처 환경의 제약은 BASE-01 수행 당시의 기록이다.

기준일: 2026-11-17  
기준 제품: 루트 `frontend/index.html`로 생성하는 오늘의 모먼트 메인 앱  
용도: 순수 JavaScript 화면을 Vue로 이식할 때 확인할 현재 디자인·화면·상태 기준. 새 Vue 화면의 전후 비교에 사용한다.

## 1. 기준의 근거와 우선순위

문서에 기록된 날짜나 이름만으로 최신 화면을 판정하지 않는다. 현재 동작 기준의 우선순위는 다음과 같다.

1. 현재 메인 화면 원본: `frontend/templates/shell.html`, `frontend/scripts/*.js`, `frontend/styles/*.css`, `frontend/design/tokens/*.json`, `frontend/design/assets/manifest.json`.
2. 현재 화면과 상태의 가장 최근 서술: [UI_SPEC.md, 2026-11-14 최신 화면 절](../UI_SPEC.md#현재-화면-요약-홈과-테마-갤러리-2026-11-14), 변경 검토: [2026-11-16 UX 리뷰](UX_REVIEW_2026-11-16.md).
3. [디자인 작업 안내](README.md)와 [토큰·레이아웃 기준](FOUNDATIONS.md), [LAYOUT.md](LAYOUT.md), [자산 기준](ASSETS.md).
4. 과거 메인 개편 보고서, 생성된 디자인 검토 화면·와이어프레임, 격리된 `design-lab/` 시안.

명세와 현재 소스가 다르면 현재 소스의 실행 가능한 메인 동작을 채택하고 본 문서의 명세 차이 표에 남긴다. 디자인 검토 페이지와 생성 HTML은 증거이자 참고이며 현재 제품 구현의 대체 기준이 아니다. 실제 기록·원문은 캡처에 사용하지 않는다.

## 2. 현재 실행 화면

### 2.1 작성 홈

- PC 기본 기준은 1366×768이다. 전체 셸은 중앙에 정렬하고 홈 작성·요약 영역을 3:2 열로 둔다. 홈은 최대 너비 1120px이다.
- 작은 화면 기준은 390×844, 360×640, 최소 폭 대표 사례는 320×568이다. 959px 이하에서는 1열로 전환한다. 새 높이별 예외를 추가하지 않는다.
- 작성창은 “오늘은 어떤 하루였나요?” 제목, “한 줄만 남겨도 괜찮아요.” 안내, 10,000자 입력과 자동 저장 상태, 별도 기록 저장 동작을 제공한다.
- 최신 상태에는 최신 카드 상태와 최근 기록 최대 3편을 표시한다. 첫 기록 전에는 합성 없는 시작 안내와 분석 준비 상태를 보여 준다.
- 기록을 저장해도 홈 작성 화면에 머무른다. 초안과 기존 선택 테마는 유지한다.
- 상단은 오늘·기록·메뉴 구조다. 통계·도감·설정은 메뉴에서 접근한다.
- 화면 전체가 필요하면 스크롤한다. 본문·패널 안쪽에 임의의 고정 높이 스크롤을 추가하지 않는다.

### 2.2 기록·상세·감정 카드

- 기록 목록은 한 열이며 작성 시각·날짜·원문 미리보기·저장·분석 상태를 쉽게 구분한다. 검색·날짜·즐겨찾기·감정 필터와 최신/오래된 순 정렬을 제공한다.
- 상세는 기록 읽기, 뒤집는 카드, 이미지 저장, 더보기 메뉴를 제공한다. 실제 분석이 준비되지 않은 경우 카드에 모델 결과를 꾸미거나 실제 분석인 것처럼 표시하지 않는다.
- 카드 프레임은 2:3, PNG 내보내기는 1080×1620이다. PNG에 기록 원문을 포함하지 않는다. 카드 효과는 화면에서만 작동하고 정적 PNG·목록 썸네일에는 넣지 않는다.
- 캐릭터와 중립 4종 표식은 `frontend/design/assets/manifest.json`, 원본은 `frontend/assets/characters/`를 기준으로 한다. forest·sunset·starlight 원본은 `frontend/assets/themes/` 아래 SVG다. IBM Plex Sans KR과 사용권 문서는 유지한다.
- 현재 분석을 저장하지 않는 메인 스토리지는 분석을 로딩 때 pending으로 정규화한다. 카드 이미지와 단계가 실제 기록의 분석 결과를 뜻하는 것처럼 보이게 하지 않는다.
- 유효한 합성 분석으로 만든 테스트 카드는 화면 검수 데이터다. 기록 텍스트는 합성된 짧은 문장만 쓴다. 테스트 합성 카드에서 단계 수치 자체를 시각 디자인 재설계로 오인하지 않도록 전환 시의 기존 정책·신규 정책을 표시한다.

### 2.3 통계·도감·설정·테마

- 통계는 감정 추이·월간 기록·감정 분포를 전환하며 기록 수·작성일 수·분석 가능·미분석 수와 월 선택을 함께 보여 준다. 분석 누락은 중립 감정으로 채우지 않는다.
- 추이 차트에는 긍정·부정·중립 계열과 `선 끊김 = 분석 없는 날` 안내를 표시한다. 수치나 문구는 카드 단계나 감정 강도로 표현하지 않는다.
- 감정 분포는 합성 분석에서만 3대분류와 10개 세부 분류를 시각적으로 구분한다.
- 도감은 10개 감정 유형 × 3단계의 30개 슬롯이다. 잠김, 열린 슬롯, 연결 기록을 구분한다.
- 설정 데이터 관리는 기록의 로컬 저장, 내보내기·가져오기, 초안·기록 삭제를 포함한다. 불러오기 동의·삭제 확인과 저장 상태를 보존한다.
- 테마 갤러리는 기본 540px 초과에서 3열, 이하에서 2열이다. 현재 실제 토큰에는 blossom·paper·sage·aurora·editorial·retro·lemon·forest·sunset·starlight **10개 테마, 각 light·dark 2개 모드, 총 20개 조합**이 있다. 최신 설명 중 `UI_SPEC.md`의 9개 썸네일 문구는 코드와 불일치하는 이전 수치다.
- 적용 전 미리보기의 테마·모드는 임시 선택이다. `이 테마 적용`만 확정 동작이다. 미리보기의 기록은 제품 예시용 고정 합성 문장이다.

## 4. 고정 합성 검수 데이터

기존의 저장·이전 로직에 데이터를 기록하지 않고 뷰에 전달한다. `frontend/scripts/app.js` 및 뷰의 합성 예시 형식을 따른다.

| 데이터 ID | 합성 데이터 | 목적 |
|---|---|---|
| `base-empty` | 새 초안·저장 기록 없음 | 기본 홈, 비어 있는 최근 기록, 시작 안내 |
| `base-pending` | `BASE-01 합성 기록: 하루의 작은 순간.` / 대기 상태 | 작성 후 대기 카드·목록·통계 누락 문구 |
| `base-valid-boundary` | `BASE-01 합성 카드: 창가에 앉아 따뜻한 차를 마셨다.` / 유효 분포 / 요청 메타데이터는 고정 | 카드·도감·분포 테스트; 실제 입력·사용자 분석으로 표시 금지 |
| `base-error` | `BASE-01 합성 실패 기록.` / 오류 상태 | 분석 실패와 보관 성공·실패의 구분 |
| `base-many` | 이름·시간이 서로 다른 최대 30건의 한글 합성 기록 | 목록 검색·필터·정렬·페이지네이션·월 통계 |
| `base-themes` | 테마 미리보기용 기존 고정 샘플 문구 | 20개 팔레트 검수; 실제 다이어리 원문 사용 금지 |

각 고정 분석은 `taxonomy_version: emotion-cardex-3plus10-v1`, `status: valid`, `version: 1`, `truncated: false`를 기본으로 하며 전체 10확률 합계가 1인 데이터를 사용한다. 카드 경계의 회귀 벡터는 0, `1/3±ε`, `1/3`, `2/3±ε`, `2/3`, 1이다. 유효 분포에서는 대표감정의 확률을 대상값으로 두고 나머지 아홉 값에 남은 확률을 균등 분배한다. 0은 정상적인 합계 1 분포가 아니므로 UI 화면 회귀 입력이 아니라 무효 응답 시나리오로만 사용한다. 테스트 데이터에 사람 이름·개인 원문·외부 식별자를 사용하지 않는다.

새 스크린샷을 재현할 경우 날짜·시간·화면 크기·모델 네트워크 요청은 고정하거나 차단한다. API 응답은 이 fixture의 mock을 사용하며 모델 가중치를 연결하거나 실제 분석 API를 호출하지 않는다. home 상태는 빈 화면과 합성 대기 기록 상태를 각각 제공한다.

| `B01-ANALYSIS-PENDING` | 합성 기록의 분석 준비 상태 | 390×844 | 기존 캡처와 비교 UI_SPEC 2026-11-16 분석 준비 문구 | 작성 보관 성공과 모델 미준비 상태의 독립 표현 |
| `B01-ANALYSIS-ERROR` | 합성 기록의 분석 오류 상태 | 390×844 | 해당 화면의 기존 캡처 없음 | 저장 오류·분석 오류 혼동 방지, 합성 오류 캡처 생성 |

| `B01-THEME-DIALOG` | 합성 미리보기, 테마 적용 전 | 390×844, 1366×768 | 해당 기존 메인 보고서에 미리보기 캡처 없음 | 오버레이·본문 스크롤·확정 버튼·초점 복귀 |

`reports/record-ui-2026-11-09/README.md`는 검증 환경 설명과 합성 전후 비교를 보존하지만 일부 이미지 링크는 `.backups` 밖의 현재 저장소에서 해석되지 않는다. 이 기준선은 실제 저장소에서 링크와 이미지 파일이 열리는 이전 홈 캡처만 과거 기준으로 표시한다. `.backups` 안의 이미지 이름을 새 캡처·현재 검증으로 재명명하거나 복사하지 않는다. 캡처가 없는 화면은 이전 상태와 후속 Vue 상태를 나란히 생성하는 것이 인수 조건이다.

새 캡처 대상은 위 표에서 기존 증거가 누락된 `STATISTICS`, `CATALOG`, `SETTINGS`, `ANALYSIS-ERROR`, `THEME-GRID`, `THEME-DIALOG`을 우선한다. Chrome과 프로젝트의 기존 Playwright 런타임이 준비되면 화면 ID·이름·뷰포트를 포함한 캡처 매니페스트에 파일별 상태, fixture ID, 날짜, 브라우저 버전을 함께 기록한다. 제품 코드는 변경하지 않는다.

## 6. 스타일과 접근성 체크 목록

- [ ] 20개 테마/모드에서 본문·보조문구·경계·상태·감정의 색과 대비가 유지된다.
- [ ] 제목·본문·보조 글자·버튼 크기·행간·줄바꿈 위치와 입력 글꼴이 일치한다.
- [ ] PC와 959px 이하 배치 및 540px 갤러리 그리드 전환이 기존 시점과 일치한다.
- [ ] 320px에서 가로 스크롤이 생기지 않고 저장 동작을 찾을 수 있다.
- [ ] 공통 셸과 홈의 너비·간격·정렬, 패널 내부 여백·모서리·그림자가 동일하다.
- [ ] SVG 아이콘·캐릭터 크기와 위치, 카드 비율·3D 효과, 테마 배경의 겹침이 동일하다.
- [ ] hover·active·focus-visible·disabled·pressed 상태의 윤곽·색·동작을 각 화면에서 확인한다.
- [ ] 카드 뒤집기 키보드 동작, 팝오버·대화상자 닫기와 초점 복귀를 확인한다.
- [ ] 분석 대기·분석 실패·저장 실패·빈 결과 문구와 `aria-live` 상태를 구분한다.
- [ ] 실 기기 터치·드래그·스크롤과 키보드 표시 시 UI 가림을 검증한다.
- [ ] 애니메이션이 실행되는 동안 캡처 시점이 흔들리지 않게 하고, 모션 설정 결과도 확인한다.
- [ ] `Error`, 새 래퍼·내부 스크롤, 안 쓰이는 탭 이동·끊어진 자산·브라우저 콘솔 오류를 기록한다.

검수 표에는 항목별로 이전·이후 값, 판단, 캡처 파일, 필요한 수정, 예외 승인 주체를 남긴다. 명세 차이·감정 분류 정책 변경은 디자인 버그와 나누어 기록한다.

### BASE-01 검증 결과

- 검토한 파일과 현행 규칙은 이 문서의 2·3·7절에 명시했다.
- 완전히 합계가 1인 합성 감정 분포와 실제 문장 입력이 없는 디자인 상태 정의를 4절에 기록했다.
- 기존 디자인 증거와 향후 기준 캡처 목록을 구분해 5절에 작성했다.
- 저장소의 Playwright 설정은 `frontend/tests/browser-runtime.cjs`, `frontend/tests/home-view.cjs`와 `reports/record-ui-2026-11-09/README.md`에서 확인했다. 현재 워크스페이스에서는 Node 실행기와 스크립트가 사용할 Playwright 경로가 확인되지 않아 새로운 실제 브라우저 캡처·2026-11-17 렌더 확인은 완료되지 않았다. 과거 루트의 모바일·PC 이전 화면 2종은 기존 캡처로 명시했고, `.backups/`에만 남은 이미지의 일부는 보존 위치를 그대로 표기했다. 수정 중 중복 캡처를 신규 증거로 복사하거나 게시하지 않았다.
- 이 작업에서 앱 코드·디자인 파일·기존 캡처 파일은 변경하지 않았다. 변경본은 이 기준 문서와 주 인수인계 문서의 링크만 추가한다.
